# Images — `save`, `load`, `insert`

Companion to [`../lens-text-mode-environment.md`](../lens-text-mode-environment.md).
Settles plan requirement (b), including what "possibly overwriting
particular previous definitions" means precisely.

> **Revision note (2026-09-06, after architecture review).** The first draft
> had a two-layer image (verbatim module text + printed ground facts) and
> it did not survive contact with the environment's own central gesture.
> Three holes: an in-place redefinition (UI.md G3.3) makes the retained
> module text stale, so `save` had no defined answer; a `retract` of a
> module-defined fact is *unrepresentable* in module text, so `load`
> resurrected it; and clause order — which is trial order in this engine —
> did not survive the facts-in-one-block layout. All three are fixed by one
> mechanism, §3: an ordered change log. That log doubles as the crash
> journal the first draft also lacked (§8).

---

## 1. The three verbs

| Verb | Effect on the world | Analogue |
| --- | --- | --- |
| **save** | Write the current world to a file. World unchanged. | `Smalltalk snapshot`, `qsave_program` |
| **load** | **Replace** the world entirely, then run the startup goal. | Starting from an image |
| **insert** | **Merge** a file in under a stated overwrite policy. | `consult`/`reconsult`, filing in a change set |

`load` is destructive by definition; lens confirms it when the current
world holds unsaved runtime state. `insert` is the incremental verb and
gets used constantly.

## 2. Why the image is text, not a memory dump

The tempting design is to serialise the term graph. Rejected, structurally:

- **A dump cannot cross implementations.** A BEAM Unify has no `ConsTerm`.
  The moment an image is a C++ heap layout, requirement (c) is dead on the
  `save`/`load` axis.
- **A dump versions badly.** Every term-layout change invalidates every
  saved image, and the engine is mid-roadmap.
- **A dump is not diffable.** These files land in git beside the `.ufy`
  sources they came from. Smalltalk's opaque image is the most-criticised
  part of an otherwise excellent model.
- **The world is nearly source already.** A Unify world is a clause
  database plus the text that produced it, and re-parsing is a correct
  restore.

So: **an image is text, and loading it is replay.** No deserialiser exists
to drift out of sync with the parser.

## 3. Three layers: modules, changes, facts

The world is *not* recoverable from module text alone. Three things break
that: predicates redefined in place, clauses retracted at runtime, and
clause order (definition order is trial order, per SPEC). One mechanism
covers all three — an **ordered change log**, exactly the role Smalltalk's
`.changes` file plays beside its image.

| Layer | Written | Restored by |
| --- | --- | --- |
| **`@module`** | the source text of each loaded segment, **as it was loaded**, verbatim | re-parsing (desugarings regenerate identically) |
| **`@changes`** | an ordered log of every world mutation since: `+define`, `-undefine`, `+assert`, `-retract` | replaying in order after all modules are parsed |
| **`@facts`** | *optional compaction* of the log's surviving `+assert` entries | re-parsing |
| synthesized | *nothing* | regenerated by the parser |
| builtins | *nothing* | `World::init()` |

Module text is never rewritten, so "verbatim" stays true and `digest`
stays meaningful. A predicate edited in place appears once in its module
and once, later, as a `+define … policy=replace` entry in the log; replay
order reproduces the live world exactly, including trial order. A retracted
fact appears in its module and then as a `-retract` entry.

**Compaction** (`save --compact`) folds the log into module text where it
can — replacing the superseded clause spans, dropping retracted ones — and
is the operation that keeps long-lived images readable. It requires
per-clause source spans, which engine item E1 (provenance) provides anyway.
It is *optional*: a correct implementation of `save` never compacts, and G4
gates the uncompacted path first.

### 3.1 Why source text is retained rather than re-printed

`if`, `for` and `foreach` **desugar at parse time** into synthesized
recursive clauses named `__fe__N`, `__feb__N`, `__for__N`, `__if__N`
(`vault-unify-parser.cpp:722,1099,1354`; the REPL's `:list` filters them
out by name prefix at `unify-repl.cpp:497`). Re-printing the clause
database would emit the desugarings, not the program: a user who saved an
image and reopened it would find their `foreach` had become two mutually
recursive machine-named predicates — semantically faithful, useless to
edit. Hence module text is retained (engine item E5) rather than
regenerated, and only ground asserted facts, which never had source text,
need a canonical printer (E6).

## 4. Format

A single UTF-8 text file, `.ufyimg`, line-oriented; directives begin `@` at
column 0, everything else is ordinary `.ufy` source.

```
#!ufy-image 1
@meta engine  "unify 0.4 (a20ddda)"
@meta created "2026-09-06T14:22:10Z"
@meta lens    "unify-lens 0.1"
@startup query { boot(); }

@module 1 origin "mediaplayer.ufy" digest "sha256:1f3c…" lines 214 imports 2
room( hall );
play( $room, $track ) { ... }
@end-module

@module 2 origin "audio-lib.ufy" digest "sha256:77b2…" lines 51 imported-by 1
...
@end-module

@changes
@change 41 define module 2 policy replace keys play/2
play( $room, $track ) { device( $room, $dev ); send( $dev, "play", $track ); }
@end-change
@change 47 retract keys volume/2
volume( hall, 7 );
@end-change
@change 48 assert keys volume/2
volume( hall, 9 );
@end-change
@end-changes
```

- `#!ufy-image 1` — magic and format version on line 1. An unknown version
  is refused, not guessed at.
- `@startup` — the **startup entity** of requirement (b): a goal run after
  load completes, in a fresh query, with its output and solutions reaching
  the transcript exactly as a typed query's would. Optional; set via
  `SaveOptions.startupGoal`, the image panel, or `:startup <goal>`.
- `@module` — one per loaded segment, in load order. `origin` is
  provenance for display and "reveal in file"; `digest` lets lens say *the
  file on disk has changed since this image was saved*, the most useful
  single thing it can report when source and image diverge.
- `imports` / `imported-by` record the import graph as it was **resolved at
  save time**, so the graph is documented without being re-followed (§6).
- `@change N` entries carry the world generation they occurred at, so the
  log is orderable and merge conflicts in git are legible.

Module ids are file-local and dense; they are not session `ModuleId`s.

## 5. Overwrite policies

`OverwritePolicy` is shared by `define` and `insert`, because they are the
same operation ([SESSION-API.md](SESSION-API.md) §2.1).

| Policy | Meaning | Analogue |
| --- | --- | --- |
| `Append` | Add clauses; existing ones remain; clause order is definition order. | `assertz`; today's `unify-run` |
| `ReplacePredicates` | For every `(name, arity)` **defined in the incoming text**, retract all existing clauses of that key first, then add. Keys not mentioned are untouched. | `reconsult` |
| `ReplaceModule` | Retract everything previously loaded under the same origin, then add. | Filing in a new change-set version |

`ReplacePredicates` is the default for `insert` and for redefining from the
source panel: it is what "overwriting particular previous definitions"
asks for, and it is what makes an incremental session survivable — you fix
`route/3`, insert, and the old clauses do not linger to be tried first.
`Append` stays the default for a transcript line, because typing a fact at
a prompt must add a fact.

`Defined` reports `added`, `replaced` and `removed` separately, so the
transcript can say `route/3 replaced (4 clauses)` instead of falling silent
about a destructive operation.

### 5.1 Atomicity — and why it is not free

`insert` must be **all-or-nothing with respect to parse errors**: parse
first, and if there were errors, retract nothing and add nothing.
Half-applying a `ReplacePredicates` insert would silently delete working
code, which is the one failure an incremental environment must not have.

The first draft claimed this was "implementable on the current engine:
parse into a staging `ExecutionState`, then splice". That was wrong, and
the reason matters:

- `parseExecuteSegment()` is an **interleaved parse-and-execute loop**
  (`vault-unify-runtime-context.cpp:158-222`). Each top-level item is
  appended to the hardwired `m_esRoot` as it is parsed; a `query { … }`
  block **launches a `SolveJob` on the spot**, mid-parse; an `import`
  reads and recursively parses inline.
- `ExecutionState::fork()` exists but the header calls it and
  `m_listChildStates` "unused, dead code" (`vault-unify.hpp:414,444`).
- Even a staging parse writes into the live `World`
  (`setTermDebugInfo`, `adoptFileDebugInfo`).

So atomicity requires real engine work, tracked as **E12**: parameterise
the parse target, defer clause installation to an explicit commit, and
route debug-info registration through the staging target. The splice
itself is easy (append-only list, tombstone retract) — the staged parse is
the 80%.

**Embedded queries cannot be staged at all.** A `query { … }` in inserted
text may `assert`/`retract` against the live world; there is no rollback
for that and there will not be one. Defined behaviour: `insert` **rejects**
text containing a top-level `query` block, with a diagnostic saying so, and
directs the user to `define` (transcript semantics) if they meant to run
it. Silently executing half a file's side effects and then failing to
install its clauses would be the worst available outcome.

## 6. Imports are not re-followed — and that costs a parser mode

An image is self-contained: every imported file was itself captured as its
own `@module` block at save time, so `load` must **not** re-follow
`import` statements inside module text. This keeps an image reproducible on
a machine that does not have the imported sources — most of the point of
having one.

The mechanism is not free, and the first draft glossed it:

- The parser executes imports inline (`processImport`,
  `vault-unify-runtime-context.cpp:129+`), so suppression needs a parse
  mode, not a convention. Engine item **E13**.
- The once-registry is keyed by `boost::filesystem::canonical()` absolute
  paths (`vault-unify.hpp`, `m_importedFiles`), which **cannot be computed
  on a machine lacking the files**. So on load, the registry is pre-seeded
  by the image's `origin` strings rather than by canonicalising them, and
  a post-load `import "audio-lib.ufy"` typed in the transcript resolves
  against that seeded set — otherwise it would silently duplicate a module
  already present. Also E13.

Mutually dependent modules are fine: clause resolution is late-bound, so
module order within an image never matters for correctness, only for trial
order — which the log preserves.

## 7. `load` needs something the engine does not have

`load` replaces the world. A `RuntimeContext` binds one Engine and one
World for its lifetime, `m_esRoot` is fixed at `setupDone()`, and
`~RuntimeContext` deliberately leaks the Engine because there is no
shutdown path (`vault-unify.hpp:2253` comment; ROADMAP 5.1 open).
Implementing `load` as "tear down and rebuild a `RuntimeContext`" therefore
leaks a worker thread per load — unacceptable in a session where load is a
normal gesture.

This is engine item **E9** (world reset), and it was missing from the first
draft's list entirely. Minimum viable form: a `RuntimeContext::resetWorld()`
that drains the engine's queues, releases the old `WorldPtr`, installs a
fresh `World` and root `ExecutionState`, and reuses the existing worker
thread. It is a subset of ROADMAP 5.1's shutdown work, not a replacement
for it.

## 8. Journal and crash recovery

The `@changes` log is the same data a session accumulates as it runs, so
lens writes it continuously to a sidecar `<image>.ufyjournal` as changes
happen, `fsync`-batched. On start, an image with a non-empty journal offers
recovery: replay the journal on top of the image and continue.

This is Smalltalk's `.changes` file, and it is the mechanism that made the
image loop *safe* — an environment whose pitch is "a world you can keep"
must not lose a session to a power cut between saves. The first draft
invoked the image and omitted the journal; that was the largest conceptual
gap in it.

`save` compacts the journal into the image and truncates it.

## 9. `save` atomicity

`save` snapshots at a single world generation: it takes
`World::currentGeneration()` and reads the clause database as of that
generation, using the same mechanism `ExecutionState::ClauseIterator`
already uses for the logical update view. A concurrent `assert` therefore
lands either wholly inside or wholly outside the image, never half. The
file is written to a temporary and renamed, so an interrupted save never
destroys the previous image.

## 10. Acceptance obligations

Gate G4 in [ACCEPTANCE.md](ACCEPTANCE.md); listed here because they define
the format as much as §4 does:

1. **Round trip.** `mediaplayer.ufy` → save → load in a fresh session →
   golden query output byte-identical to the original run.
2. **Runtime state survives.** Assert three facts, save, load: identical
   catalogue and identical answers.
3. **Desugaring survives.** A program using `for`/`foreach`/`if`
   round-trips, and its `@module` block contains the original text, not
   `__fe__` clauses.
4. **Edit-then-save composes.** Redefine a predicate in place (G3.3), save,
   load: the world matches the live one, including trial order. *This is
   the case the first draft could not answer.*
5. **Retraction survives.** Retract a module-defined fact, save, load: it
   stays gone.
6. **`ReplacePredicates` is precise.** Exactly the incoming keys change.
7. **Failed insert changes nothing.** A parse error under
   `ReplacePredicates` leaves the world bit-identical; diagnostics reported.
8. **Embedded query is rejected**, with the diagnostic, and nothing applied.
9. **Startup goal runs**, its output reaches the transcript, and a failing
   startup goal reports without aborting the load.
10. **Version refusal.** `#!ufy-image 2` is refused, not partially read.
11. **Journal recovery.** Kill lens mid-session; restart; the recovered
    world equals the pre-kill world.
12. **Compaction is behaviour-preserving.** `save` and `save --compact` of
    the same world load to worlds that answer the golden query set
    identically.
